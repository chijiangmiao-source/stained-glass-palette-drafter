# 彩窗玻璃色号映射工具

老建筑彩窗修复辅助工具：把低分辨率 PNG 复原稿的每个像素归入唯一色号，统计各色玻璃用量并导出采购清单。纯前端实现（TypeScript + Vue 3 + Vite），文件仅在浏览器内用标准能力解码，不上传、不调用任何外部服务。

## 功能规则

### 输入

- **图片**：PNG 文件，宽、高各 1–128 像素。
  - 完全透明（alpha = 0）的像素视为空格；
  - 任一像素透明度不是 0 或 255 时拒绝整图；
  - 非 PNG、解码失败、尺寸越界同样拒绝，并清除旧版图、明确报错。
- **色板**：2–16 个依次排列、互不重复的六位大写十六进制色值（如 `FF0000`），每行一个（也接受空格/制表符分隔）。色板非法时清除旧版图并明确报错。

### 映射

不透明像素直接采用 8 位 sRGB 整数，计算其与各色板颜色的三通道差值平方和并取最小者；并列时取色板中最靠前者。不做伽马转换、抖动或邻域修正。

### 人工校色

- 自动配色后，制版师可点击任一**非透明格**，从现有色板中选择替代色；
- 格子立即标记为「人工指定」（格角圆点），色片统计、网格颜色与导出预览同步刷新；
- 再次打开该格可一键**恢复自动计算结果**；
- 透明空格不可校色，点击时仅给出明确提示，不改变任何结果；
- 上传新图片或（重新）应用色板会清空全部人工指定；
- 每格同时记录自动命中与可选人工命中，映射层集中合成最终色号，网格、统计与导出始终以合成结果为唯一来源；未做任何校色时，下载内容与自动配色版本逐字节一致。

### 展示

- 可缩放的编号网格（行、列编号均从 1 开始），空格以棋盘格表示；
- 悬停任一格子显示行号、列号、原色与目标色；
- 汇总每种色板颜色的片数。

### 映射质量核查

- 自动映射与人工校色完成后，可在「映射质量核查」面板输入允许的色差上限（三通道差值平方和，0–195075 的整数），点击「开始核查」；
- 色差按**原像素与最终选色**（含人工校色）逐格计算：严格大于上限的格子计入超限，等于上限不算超限；全透明空格不参与核查；
- 面板展示超限格数量、最大偏差，以及按行号、列号（行优先）排序的明细（行列、原色、最终选色、色差）；网格同步用红色描边标出这些格子；
- 质量计算直接读取现有最终映射结果与色板，人工改色后核查结果即时重算，明细、网格标记与统计始终对应同一批格子；
- 空值、小数、负数或越界上限会在面板明确报错，并保留上一次有效结果（未开启时不会因非法输入而开启）；全透明版图显示零个超限格；
- 上传图片、（重新）应用色板（含其报错）或点击「结束核查」都会结束核查，网格恢复原显示；
- 核查不改变任何映射结果：采购文本与备料核验单只按原有映射变化规则更新；未开启核查时，网格交互、缩放与下载内容保持原样。

### 导出

- 按行优先记录非空格像素，每行一条记录：`行号<TAB>列号<TAB>色板序号`（均从 1 开始）；
- 三个字段以单个制表符分隔，记录以 LF 分隔，文件末尾不换行；
- 无不透明像素时导出空文件；
- 网格、统计与导出内容同源，逐格一致。

### 备料核验

- 映射与校色完成后，可在「备料核验」面板逐色录入库房可用库存（非负整数），生成独立的核验单；
- 核验单以生成时的最终色片数为需求快照，按色板顺序逐色计算：领用量 = min(需求, 库存)、剩余量 = 库存 − 领用量、缺口 = 需求 − 领用量；
- 全部色号缺口为 0 时汇总为「可直接备料」，否则为「库存不足」；
- 空值、负数、小数或超出安全整数的库存会定位到对应色号并阻止生成；合法的零库存仍参与缺口计算；
- 生成后再人工校色、换图或重应用色板时，旧核验单保留为已过期快照并提示重新生成；
- 核验不改变网格、统计与采购文本；「清空」只移除核验单与库存草稿。

### 装箱批次

- 映射与校色完成后，可在「装箱批次」面板输入每箱容量（1–999 片的整数）并创建批次单；
- 批次单按最终映射（含人工校色）把每个非透明格编入唯一批次：按色号分组、同色相按行列顺序排列，同色数量超过容量时连续拆箱，箱号按色板顺序从 1 开始连续编号；
- 页面按色板顺序展示各箱编号、色号、坐标范围与片数；逐箱「标记已装」后即时更新完成比例与下一箱提示，全部装完显示完成态；
- 容量为空、小数、负数或越界时定位报错并保留已有批次单；全透明版图提示没有可装箱玻璃，不创建记录；
- 人工校色、换图或（重新）应用色板会清除批次单，避免现场继续使用与当前版图不符的计划；
- 装箱不改变网格、统计、质量核查、备料核验与采购文本。

## 本地开发

```bash
npm install
npm run dev          # 开发服务器
npm run build        # 构建到 dist/
npm run typecheck    # vue-tsc 类型检查
npm run test:unit    # Vitest 单元测试（映射与导出核心逻辑）
npm run test:e2e     # Playwright 端到端测试（自动构建并自起 preview 服务）
npm run verify       # 一次性验收：单元测试 + 端到端测试
```

## Docker 发布与验收

```bash
# 发布页面（默认宿主端口 8080，可用 WEB_PORT 覆盖）
docker compose up -d web
WEB_PORT=9000 docker compose up -d web

# 一次性验收：构建并运行名为 verify 的服务（Vitest + Playwright），
# 针对 compose 网络内的 web 服务执行，结束后自动退出
docker compose up --exit-code-from verify verify
# 或者反复验收：
docker compose run --rm verify
```

- `web` 服务：多阶段构建，nginx 托管 `dist/` 静态页面，宿主端口由 `WEB_PORT` 控制（默认 8080）。
- `verify` 服务：基于官方 Playwright 镜像，先跑 Vitest 单元测试，再对 `http://web:80` 跑 Playwright 端到端测试，覆盖映射与导出，运行一次后退出。

## 目录结构

```
src/
  core/            # 纯逻辑：色板解析、像素映射、人工校色合成、导出文本、质量核查、备料核验、装箱批次、PNG 解码、布局常量
  components/      # GridView（可缩放编号网格）、StatsTable（用量统计）、QualityCheck（映射质量核查）、InventoryCheck（备料核验）、PackingPlan（装箱批次）
  App.vue          # 页面组装与状态流转
tests/
  unit/            # Vitest：色板校验、映射规则、导出格式、质量核查、备料核验、装箱批次
  e2e/             # Playwright：完整流程、错误处理、边界尺寸、导出下载、质量核查、备料核验、装箱批次
Dockerfile         # web 服务镜像（构建 + nginx 发布）
Dockerfile.verify  # verify 一次性验收镜像
docker-compose.yml # web + verify 编排，WEB_PORT 覆盖宿主端口
```
